用 **本地 3B 小模型** 跑通 OpenAI Deep Research 同款形态的调研 Agent：
输入一个调研问题，自动完成 **规划 → 联网搜索 → 网页阅读 → 反思补搜 → 分节成文 → 自审修订**，
产出带引用来源的 Markdown 调研报告。

> **核心命题：大模型人人会调，把 3B 小模型的工程可靠性做上来才是本项目的亮点。**
> 所有架构决策都围绕"把开放推理降级为受限选择"展开，
> Agent 循环、工具调用、结构化输出、评估体系全部手写实现（零 LangChain/LlamaIndex 依赖），
> 并用数据量化每项手段的收益。

## 为什么值得一看

- **证据链优先**：原文全文＋发布机构/日期入库，表格数字确定性解析（含单位换算）——数据不经过 LLM 转写，核验时能一路追回原文
- **结构化写作**：3B 排版引用常错位，改为模型输出「事实句＋来源编号」、程序排版引用，每句话的依据可程序化检查
- **双反思闭环**：搜完反思"资料够不够"（阶段C），写完自审"报告对不对"（阶段E）——数字·单位·年份·口径逐句比对，未解决的问题保留在报告头部，不静默清零
- **三层可靠性防线**：非法工具调用回喂自修复 → JSON-ReAct 降级 → 规则确定性兜底，专治 3B 的参数幻觉与空转
- **搜索质量治理**：大纲空词自动改写、权威域名分层加权、非权威域单位内部页拒收、题库/文档站黑名单、脚本/验证页拒收、发布日期提取与时效偏好
- **可复现评估**：搜索快照磁盘回放（零 API 消耗对比实验）+ 消融实验 + 引用忠实度校验（如实报告核验覆盖范围）
- **消费级显卡可跑**：4GB 显存的入门 GPU 即可全流程本地运行，`local` 搜索源零 API key 开箱即用

## 架构

```
调研问题
   │
   ▼
┌─────────────────────────────────────────────────────────────┐
│ A 规划 Planner                                               │
│   JSON Schema 约束 + pydantic 校验 + 失败回喂修复重试          │
│   → 大纲 3-5 节 + 初始搜索词 2-4 个（禁止大纲式标题词）         │
├─────────────────────────────────────────────────────────────┤
│ B 信息收集 Researcher（ReAct 工具循环，核心）                  │
│   Ollama 原生 tool calling，仅 2 个单参数工具：               │
│     web_search(query) / read_page(path)                      │
│   防线1 非法调用 → 错误回喂自修复                             │
│   防线2 连续失败 → 降级 JSON-ReAct（提示词动作选择）           │
│   防线3 整轮无产出 → 规则兜底采集（确定性脚本）                │
│   查询词治理：大纲空词自动拼问题核心词改写                     │
│   结果治理：相关性过滤 + 权威加权 + 单位页面降权 + 黑名单      │
│   页面质检：脚本/验证页/推荐区拒收，无关正文不入库             │
│   证据链：原文全文 + 发布机构/日期入库；摘要为抽取式，          │
│   表格数字确定性解析（含单位换算），不经过 LLM 转写            │
├─────────────────────────────────────────────────────────────┤
│ C 反思 Reflector（搜-反思闭环）                               │
│   「信息够不够」降级为 sufficient + gap_queries 受限输出       │
│   覆盖度规则兜底：任一小节相关来源 <2 条 → 强制补搜            │
├─────────────────────────────────────────────────────────────┤
│ D 写作 Writer（结构化观点，引用由程序排版）                    │
│   分节生成（每节只注入相关性 top-3 原文证据）                  │
│   模型输出「事实句＋来源编号」JSON，程序给每句附加引用          │
│   编号白名单校验，非法条目回喂重试；整节跑题纠偏失败 → 占位     │
├─────────────────────────────────────────────────────────────┤
│ E 自审 Reviewer（写-反思闭环，对称于 C）                      │
│   ① 规则层(免费)：占位节可补 / 缺引用 / 数字·单位·年份·口径比对 │
│   ② LLM 逐句裁决：按原文证据判 支持/部分支持/不支持            │
│   → 触发补搜（接回 B）+ 重写问题节 → 再审一次                  │
│   未解决问题不清零：报告头部标注核验状态与待核验章节            │
└─────────────────────────────────────────────────────────────┘
   │
   ▼
reports/*.md 调研报告   +   traces/*.jsonl 全链路追踪
```

## 快速开始

**前置要求**：Python 3.10+，[Ollama](https://ollama.com) 已安装。

```bash
# 1. 拉模型（约 1.9GB）
ollama pull qwen2.5:3b

# 2. 安装依赖
git clone https://github.com/dhanegle/deep-research-agent.git
cd deep-research-agent
python -m venv .venv
.venv\Scripts\pip install -r requirements.txt   # Windows
# source .venv/bin/activate && pip install -r requirements.txt  # Linux/Mac

# 3. 配置（默认 local 搜索源，零 API key 开箱即跑）
cp .env.example .env

# 4. 跑第一个调研（检索 data/ 示例语料，不联网）
.venv\Scripts\python -m agent "2025年国产新能源汽车出口情况" --provider local

# 5. Web UI（推荐）：输入问题 → 实时看到每个阶段 → 渲染报告与指标
.venv\Scripts\python -m agent.web
# 浏览器打开 http://127.0.0.1:8080

# 6. 真实联网调研（三种搜索源见下表）
.venv\Scripts\python -m agent "固态电池产业化最新进展" --provider bocha
```

> 单元测试不依赖 Ollama 和网络，随时可跑：`.venv\Scripts\python -m pytest tests/ -v`

### 三种搜索源（同一 SearchProvider 接口，可插拔）

| 搜索源 | 说明 | 适合 |
|---|---|---|
| `local` | 把 `data/` 文件夹当语料库：关键词滑动切分对文件名+正文打分；支持 md/txt/pdf/docx | **零配置开箱体验**、离线场景 |
| `bocha` | [博查 AI 搜索](https://bochaai.com)（国内），中文召回好，直连无需代理 | **中文调研推荐** |
| `tavily` | [Tavily](https://tavily.com)，英文场景召回优，有免费额度 | 英文调研 |

联网源只需在 `.env` 里填对应 API key，Web UI 下拉框也可直接切换。

## 评估体系

三层设计，保证 **可复现、可对比、可量化**：

1. **磁盘快照回放**：搜索与网页抓取按内容哈希落盘。首次 `CACHE_MODE=record`
   真实请求并快照；此后 `CACHE_MODE=replay` 全程读缓存——零 API 消耗、不依赖网络、
   结果逐位可复现，是提示词对比实验的基础设施。
2. **评测集**：`eval/tasks.jsonl` 每任务附要点评分表（must_cover 关键词）。
3. **指标**：要点覆盖率 / 结构化输出首试成功率 / 工具调用有效率 / 引用忠实度与密度 / 耗时。

```bash
# 首轮：真实搜索并落盘快照（一次性，消耗搜索额度）
CACHE_MODE=record SEARCH_PROVIDER=bocha .venv/Scripts/python eval/run_eval.py

# 之后：回放对比实验（改提示词/关反思等，零成本复跑）
CACHE_MODE=replay .venv/Scripts/python eval/run_eval.py --tag exp2
CACHE_MODE=replay .venv/Scripts/python eval/run_eval.py --no-reflect --tag baseline
```

### 实测指标（local 搜索源 2 任务 / 本机 qwen2.5:3b）

| 指标 | 数值 | 说明 |
|---|---|---|
| 任务成功率 | 2/2 | 全流程无人工干预 |
| 要点覆盖率 | 100%（9/9 关键词） | 评分表关键词全部命中 |
| 结构化输出首试成功率 | 100% | 早期版本实测曾低至 50%，修复重试兜底后始终 100% |

## 为什么这些设计对 3B 模型是必要的

每一条都来自真实 trace 复盘（`traces/*.jsonl` 全链路留痕），不是拍脑袋：

| 3B 的典型失败 | 本项目的对策 | 量化入口 |
|---|---|---|
| 工具调用格式错乱/编造参数（把 query 写成 path） | 少工具(2个)、单参数、错误回喂自修复、JSON-ReAct 降级 | tool_valid_rate / react_fallbacks |
| 给路径编造 `https://` 前缀 | 参数命名 `url`→`path` + 前缀剥离后缀容错匹配（同一任务 39%→100%） | tool_valid_rate |
| 把小节标题原样当搜索词（「政策影响因素」） | 查询词与问题核心词无实义重合时自动拼接改写；planner 提示词禁止大纲式标题词 | trace 中 query 改写记录 |
| 口语词搜索只命中学校/单位通知页 | 官方口径词提示词规则 + 权威域名加权 + **非权威域单位内部页整条拒收**（公示/通知/资格审查；原为 -0.15 降权，实测拦不住）+ 题库站黑名单 | 收录来源域名分布 / `internal_page_dropped` |
| 收录来源以报告聚合站/自媒体为主，央媒极少（实测 51 份报告权威域名仅占 4.6%，47/51 无任何权威来源） | **权威域名分层排序**（中央媒体>政府统计机构>普通站）+ 常规召回无权威时**权威定向补搜**（Tavily `include_domains` / 博查 `include`，实测央媒占比 2.8%→检索白名单内 100%） | `authority_searches` / 收录来源域名分布 |
| 收录回来的来源偏旧，且模型无从判断新旧（实测候选里 2025 年 102 条、2024 年及更早 50 条；排序 key 只有权威层级与相关度，**没有时间维度**，2025-11 的旧稿与 2026-06 的新稿同权） | **搜索结果带上发布日期**（博查 `datePublished` 实测覆盖 100%、Tavily `published_date`、URL 内嵌日期兜底）+ 候选列表标注日期 + 排序对近 180 天来源小幅加分（**只奖不罚**，见下） | `eval.freshness`：top-5 中近 180 天候选 248→274，权威条目净 +4 |
| 网页发布日期解析出错且无人校验（光明日报电子版 URL 是 `/202606/30/`，trafilatura 从页脚版权解析出 `2025-01-01`，被原样写进报告"发布于 2025-01-01"） | meta 日期与 URL 内嵌日期**交叉校验**，年份矛盾时以 URL 为准（URL 是发布系统按日期生成的路径，实测权威域覆盖≈70%） | `published_at` 与 URL 日期一致性 |
| 页面质检按字面二元组匹配，反而**拒收央媒、放行照抄查询词的聚合站**（「2026年的毕业情况」生成伪二元组「的毕」，人民网/新华网正文因不含它被整类拒收） | 虚词（的/地/得/之/了/着/在）作二元组切分点，消除跨虚词伪二元组；写作选材对权威来源放宽相关性门槛 | `source_rejected` / 各节注入来源 |
| 小节正文只沾主题词就算扣题（材料是"总人数"口径，正文写成"就业比例"，靠与问题共享的"毕业"通过扣题检查） | 小节比问题更具体时，要求命中"小节独有词"或 aspect 同义词；aspect 表补入"人数/预测/万人"等统计词汇 | 各节正文与标题一致性 / `align_feedback` 提示词 |
| 反复搜索同一关键词而不阅读（实测单轮空转 282 次） | 同轮查询去重直接顶回未读链接 + 单轮 12 次搜索预算（282→4 次） | searches / tool_calls |
| 补搜轮反复重读同一批反爬死链（实测 13 次搜索零收录） | 抓取失败/拒收的 URL 跨轮拉黑，搜索结果与兜底采集均不再重试 | scripted_read_fail / source_rejected |
| JSON 输出偶尔不合法 | format=json + pydantic 校验 + 失败回喂重试 | json_first_try_rate |
| 读 1 条就"宣布完成" | min_sources 约束 + nudge 顶回 + 反思补搜 | sources 数 / reflect_rounds |
| 把网页脚本/推荐区当正文（JS 原型链写进就业报告） | 页面质检拒收脚本/验证页 + 推荐区截断 + 无关正文不入库 | pages_rejected |
| 引用编号放错句子、审查文字抄进正文 | 结构化输出「事实句＋来源编号」，引用由程序排版；非法编号回喂重试，仍无合法内容则占位 | 报告引用合规 |
| 把本节所有编号一股脑挂在每句后（106万辆挂 [1][3][4]，只有 [1] 讲总量） | 成文时按证据确定性剪枝：对本句任何数字都没支撑、且另有编号能独立支撑整句时剔除 | num_flags / review_unresolved |
| 摘要时丢失表格单位（千美元写成百万美元，差 1000 倍） | 海关表格确定性解析并换算为绝对金额，数字不经过 LLM 转写 | evidence 归一化行 |
| 报告数字与来源对不上（年份/单位/金额·数量口径错配） | 阶段E 规则层按数值+单位+年份+口径比对 + LLM 逐句裁决；未解决问题标注在报告头部 | faithfulness / num_flags |
| 同一句事实被写进多个小节（实测 59% 的报告存在跨节重复，正文句子重复率 27.1%，最严重一份 71%；3B 会把一句政策话塞进"就业市场分析/毕业生就业意愿/政策与经济影响"三节） | 成文后确定性去重：去引用编号与归因前缀、抹平数值前虚词后按相似度判重（数字口径须相容，否则不判重），只留扣题度最高的一处；整节被判重则标注"内容与其它小节重复"的缺口，交阶段E 补搜重写 | deduped_sentences / 跨节重复率 |
| 逐字比对抓不到改述型重复（"…的报道" vs "…发布的消息"、多一个"普通"二字，字面不相等却是同一句） | 判据从"字面相同"放宽为"相似度 ≥0.85 且数字口径相容"；聚类只用于挑保留句，删除仍要求与保留句**直接相似**，避免传递性误删（实测把"硕士生招生118.57万人"和"毕业生1270万人"连成一簇） | 假阳性检查 0 例 |
| 没有时间概念，"今年/最新"按训练截止期理解 | 每次 LLM 调用注入当前日期；"今年/去年"进管线前确定性替换；发布日期≠统计期间入库即区分 | 搜索词年份 |
| 长上下文注意力衰减 | 网页→抽取式证据片段，每节只注入 top-3 相关原文证据 | token 用量 |

### 试过但被数据否掉的方案

留在这里是因为"做了什么"和"为什么没做"同样是设计依据：

| 方案 | 动机 | 实测结果 | 结论 |
|---|---|---|---|
| 整节只用 1 条资料时点名未用来源，催模型补充 | 实测某节注入了 3 条资料，3B 只写第一条，其余整块内容不进报告 | 5 个小节全部触发重试，3B 无视"保留已有内容"整段重写，择优后输出**一字未变**——纯多花 5 次调用 | 否 |
| 上一条改为由程序合并（保留首稿＋追加引用新来源的句子） | 不指望模型自觉保留，按项目惯例用代码兜底 | 同一批事实被塞进 3 个小节、主要发现出现近似重复条目；LLM 调用 33.5→36.5、耗时 31→37s，覆盖率与忠实度不变 | 否 |
| 非权威域的单位内部页（公示/通知）只做 −0.15 降权 | 想守"校验降级而非丢弃"的惯例，不把候选整条砍掉 | 降权拦不住：北京体育大学就业指导中心的《关于开展2026届毕业生就业意向和进展调查的通知》在 51 份报告里被收录 3 次，正文全是调查安排、没有一个统计数据，字面密度高到降权后仍进候选前 5 | 否，改为整条拒收 |
| 时效按"档位"排在相关性**之前**（近 180 天 / 未知 / 更早三档） | 想让旧内容在排序里吃亏，把新稿顶上来 | 22 份快照里出现权威倒退：央视 `edu.cctv.com`（2025-11-21）、新华网被知乎/华尔街日报替换——因为"日期未知"取中性档，而多数政府一手来源的 URL 不含日期，于是未知反超确知较旧的权威 | 否，改为**只奖新鲜、不罚旧**：近 180 天 +0.05，其余不动。权威挤出 22→3 次，补入 7 次（净 +4） |

结论一：**小模型的"内容不够广"不能靠催，问题在选材层多注入了本节用不上的资料**——
强行提高来源使用率只会把跨节冗余放大。冗余改由**成文后**的确定性去重收拾（不占生成
上下文、零额外调用）：离线回放 154 份报告，跨节重复 27.1% → 0.3%，仅 22 个小节因整节
被判重而标注缺口（最多 2/5 节），逐条人工核查无一处误删。

结论二：**"降级而非丢弃"的前提是内容本身有效**。单位内部页对统计类问题是**错标**——
它被搜索引擎按字面匹配塞进来，正文里没有一个可引用的数字，留着只会挤掉权威报道、
白费一轮抓取与摘要。因此改为拒收；同时保留两条豁免：**权威域的「通知」是部委文件**
（实测 227 条收录来源里权威域内部页仅 1 条，且是有价值的部委通知），**无域名的本地语料**
（用户自己放进 `docs/` 的文档）不由来源治理二次判断。离线回归：全量 3358 条候选将拒收
35 条（1.04%），权威域命中 0 条；历史 233 条收录来源中恰好拒收 3 条，全部是同一个
`jy.bsu.edu.cn` 通知。

## 常见问题

**Q：报告里有的节写"（本节暂缺相关资料）"？**
设计如此（宁缺毋滥）：资料与该节确实无关时不硬写。阶段E 自审会在"占位但有可用资料"时自动补搜+重写，若仍占位说明现有搜索源确实没找到对口资料——换更具体的提问或换搜索源再试。

**Q：改了代码 Web UI 行为没变？**
Python 进程不会热重载，重启 Web 服务（Ctrl+C 后重新 `python -m agent.web`）。

**Q：一定要联网 / API key 吗？**
不用。`--provider local` 检索 `data/` 示例语料即可完整体验全流程；联网源（博查/Tavily）才需要 key。

**Q：为什么搜到的是小网站而不是权威来源？**
搜索质量治理已内置（官方口径提示词 + 权威域名分层 + 非权威域单位内部页拒收 + 黑名单）。若仍遇到，欢迎开 Issue 并附上 trace 文件——这正是全链路留痕的用途（被拒收的内部页会记 `internal_page_dropped`）。

**Q：报告里引用的来源看起来偏旧？**
搜索结果现在会带发布日期（博查 `datePublished` / Tavily `published_date` / URL 内嵌日期兜底），候选列表也会标注，排序对近 `FRESH_DAYS` 天内的来源小幅加分。但时效**只奖不罚**——统计类问题常需引用历史数据，且毕业人数、年度统计这类数字本来就在前一年底发布，旧不等于错。若确认数据口径过期，把问题问得更具体（如"2026 年**上半年**的出口数据"）比调排序更有效。

**Q：4GB 显存的入门显卡能跑吗？**
能，这正是项目的基准环境：qwen2.5:3b（Q4 量化约 1.9GB）可全量驻留 4GB 显存，单次调用 1-2s、约 40s/报告。模型 + KV 缓存 + 显示占用三者合计不超显存即可。

**Q：换 qwen3 这类更新的小模型行不行？**
显存是硬约束：qwen3:4b（Q4 约 2.5GB）加上 KV 缓存超出 4GB 显存，GPU/CPU 反复腾挪会导致单次调用延迟 3~98s 剧烈波动，实测不可用；显存充裕（8GB+）时改 `.env` 的 `MODEL` 即可尝试。另有一个已写入代码的坑：ollama 0.32 的 `think=False` 参数会把 Qwen3 思维链错路由进正文污染输出，`llm.py` 已按模型族自动改用官方软开关 `/no_think`，换模型无需改代码。
